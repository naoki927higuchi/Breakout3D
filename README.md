# NEON BREAK / 3D

Unity 6000.6.2f1用の3Dブロック崩し。外部アセットは不要です。

## 遊び方

配布ZIPを展開し、中の `NeonBreak.exe` を起動してください。Unityメニューからビルドした場合は `Builds/Windows/NeonBreak.exe` に出力されます。

- マウス、左右矢印、A / D：パドル移動
- クリック / Space：発射
- R：再スタート
- Esc：終了
- M：効果音のオン／オフ（再スタートしても設定を維持）

## ルール

- 54個のブロックをすべて壊すとクリア。
- ブロックを壊すたびに全ボールの速度が0.32ずつ上昇（初速8、上限22）。
- 全ボール合計の累計破壊数が5・10・15個…に達したとき、ボールが1個ならマルチボールを予約。次にパドルで打ち返したときに2個に増加します。パドル反射やボール消失で累計はリセットされません。
- ボールが追加されたときは通常の加速に加えて全ボールの速度がさらに0.6上昇（上限22）。すでに2個なら追加も追加加速もなく、次の5の倍数で再判定します。
- 予約は画面に表示され、重複して蓄積されません。予約中でも打ち返す前に落とすとゲームオーバーです。再スタートで予約もリセットされます。
- コンボは引き続き、同じボールがパドルに戻るまでの連続破壊数として記録。最高コンボを表示します。
- 赤ブロックは2回で破壊。1回目で明るい赤色になり白いマークが消えます。
- すべてのボールを落とすとゲームオーバー。

## 効果音

ネオン調の画面に合わせたオリジナルの電子音を起動時に合成します。外部音源は不要です。
発射、パドル反射、壁反射、赤ブロックへの初撃、ブロック破壊、マルチボール予約・発生、
ボール消失、ゲームオーバー、クリアで音を使い分けます。連続破壊では音程が少し上がります。
壁の音は控えめにし、同時発音は最大8音。再スタート時には前の効果音を止めます。
音色と音量は `Assets/Scripts/BreakoutGame.Audio.cs` で調整できます。

## Unityで編集

Unity Hubでこのフォルダーを追加し、`Assets/Scenes/Breakout.unity`を開いてPlay。
ゲームの見た目と盤面は`Assets/Scripts/BreakoutGame.cs`で生成します。
X/Z平面の独自衝突処理を短い時間刻みで実行し、Y方向は3D表示に使っています。

通常ビルド：Unityメニューの **Breakout > Build Windows Player**。
既存のシーンとマテリアルを使用し、ビルドのたびにシーンを再作成しません。

## 再頒布用のビルド

プロジェクトのフォルダーでPowerShellから実行します。

```powershell
.\Build-Windows.ps1 -Version 1.0.0
```

`ProjectSettings/ProjectVersion.txt` のUnityバージョンをUnity Hubの標準インストール先から検出します。
別の場所にある場合は `-UnityEditor "D:\Unity\Editor\Unity.exe"` を指定してください。

1. 毎回新しい作業フォルダーへWindows x64版をビルド。
2. Unityランタイム、ゲームデータ、日本語の遊び方、バージョン情報をまとめてZIP化。
3. ZIPを空白入りの別フォルダーに展開し、その実行ファイルで自動テスト。
4. 成功したZIPとSHA256チェックサムを `Builds/Releases/` に保存。

ZIPにはバージョンと実行ごとの識別子が付き、以前の配布物を上書きしません。
`Builds/Runs/` に中間生成物とビルド・テストのログを保存します。
実行ファイルだけでなくZIP全体を渡してください。受け取る側にUnity Editorは不要です。
ビルド処理は外部へのアップロードを行いません。検証はこのPC上での実施であり、別PCでの動作保証ではありません。
Unityの開発用診断フォルダーは配布から除外し、必要なランタイムは同梱します。
ゲーム本体のルールや操作は変更していません。

## 自動確認

実行ファイルに `-batchmode -nographics -selftest -logFile selftest.log` を渡すと、
実際のゲームの衝突処理で赤ブロックの耐久力、加速、連続破壊、2球の上限、
パドル反射、ボール消失、再スタート、速度上限、クリア判定を検証します。
成功時は終了コード0、失敗時は1を返します。

## ローカル変更履歴

このフォルダーをGitリポジトリとして管理しています。まとまった変更と検証が完了するたびにコミットします。作業ルールは `AGENTS.md` に記載しています。

- 履歴を確認：`git log --oneline`
- 変更の内容を確認：`git show <コミットID>`
- 過去の状態を別フォルダーで開く：`git worktree add --detach ../Breakout3D-review <コミットID>`

過去の状態を開いた後は、そのフォルダーの `Build-Windows.ps1` で実行ファイルを再作成できます。
履歴の保存開始点は、累計5個破壊でのマルチボールと加速調整を実装した改善版です。それ以前の状態は履歴に含まれません。
開発中のビルド成果物やUnityのキャッシュはGit管理対象外です。公開時に選定したZIPだけをソースとともにリモートへ送ります。
